O que está configurado

O rastreamento do CEVEPE roda em dois containers do GTM trabalhando juntos: um no navegador (site) e um no servidor (via Stape), garantindo que o Meta receba os eventos por dois caminhos ao mesmo tempo, sem contar em duplicidade.

Testado e funcionando. A deduplicação do Meta foi testada no Events Manager e está validada: cada conversão chega pelo Pixel (navegador) e pela API de Conversões (servidor) com o mesmo identificador de evento, e o Meta reconhece as duas entradas como um único evento.

Como funciona

O caminho de um clique até o Meta

Todo clique num dos 5 botões de WhatsApp dispara os quatro canais ao mesmo tempo, por dois caminhos diferentes até chegar no Meta.

1
Alguém clica em um botão de WhatsApp no siteO GTM do navegador (container Web, GTM-MCQ7N3L2) identifica o clique pelo texto do botão ou pelo elemento.
2
Dois disparos acontecem em paralelo, direto do navegadorMeta Pixel envia o evento direto pro Meta, com um Event ID único. GA4 envia o mesmo evento pro Google, e também para o container servidor.
3
O container servidor recebe a cópia do eventoRodando na infraestrutura da Stape (GTM-PWXJZRVT), ele funciona como uma segunda via, mais resistente a bloqueadores de rastreamento e restrições de navegador (Safari, iOS, ad blockers).
4
O servidor reenvia o evento pro Meta via API de Conversões (CAPI)Usando o mesmo Event ID que o Pixel já enviou. O Meta recebe as duas entradas, reconhece que são o mesmo clique e conta como uma única conversão.

Por que os dois caminhos: o Pixel sozinho perde eventos quando o navegador bloqueia rastreamento. A API de Conversões sozinha não tem o contexto completo do clique. Rodando os dois juntos, com deduplicação pelo Event ID, o CEVEPE tem o dado mais completo possível sem contar conversão em dobro.

Qualidade do dado

Deduplicação no Meta

Confirmado nos dois containers: os 5 eventos usam exatamente o mesmo nome em todos os pontos da cadeia, do clique no site até o servidor.

  • No navegador, o Meta Pixel envia cada evento com um Event ID único gerado no momento do clique.
  • O mesmo clique dispara o GA4, que carrega esse identificador junto e o envia também para o container servidor.
  • No servidor, a tag oficial da Stape de API de Conversões do Meta escuta os 5 nomes de evento (whatsapp_topo, whatsapp_botao, whatsapp_urgencia, whatsapp_duvidas, whatsapp_agenda) e reenvia cada um preservando o mesmo Event ID.
  • O Meta recebe as duas entradas com o identificador batendo e junta as duas em uma única conversão contada.

Resultado do teste: no Events Manager do Meta, os eventos de Pixel e de API aparecem casados (mesma fonte de evento, sem duplicidade na contagem), confirmando que a configuração está correta ponta a ponta para as 5 conversões.
